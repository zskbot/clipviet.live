1. Tổng quan

ClipViet cung cấp giao diện catalog và các dịch vụ Worker tách biệt. Catalog API phục vụ đọc metadata; Provider Registry quản lý trạng thái nguồn, quyền nội dung, connector và kiểm tra playback. API không đồng nghĩa với quyền phân phối nội dung.

READ-ONLY CATALOG

Danh mục, tìm kiếm, phân trang và thông tin video.

PROVIDER REGISTRY

Trạng thái provider, kiểm duyệt quyền và chẩn đoán.

3. Unified Video API

Single public read endpoint: GET /api/videos

Đây là API chuẩn duy nhất mà frontend ClipViet sử dụng. Năm provider API hiện được đăng ký trong cùng một gateway nhưng vẫn ở trạng thái PENDING; chưa có nguồn nào được cấp quyền phân phối đã xác minh, vì vậy API chưa gọi upstream và không trả URL media.

GET/api/videos?page=1&limit=30&keyword={keyword}

Trả về catalog đã chuẩn hóa, phân trang thống nhất. Hiện tại trả results: [], trạng thái quyền và danh sách provider; chỉ các nguồn được duyệt mới được phép đóng góp dữ liệu.

{
  "success": true,
  "endpoint": "/api/videos",
  "version": "1.0.0",
  "mode": "rights-gated-unified",
  "pending": true,
  "results": [],
  "items": [],
  "page": 1,
  "limit": 30,
  "total": 0,
  "pageCount": 0,
  "providers": [
    {"id":"souavzy","status":"PENDING","enabled":false},
    {"id":"apiyutu","status":"PENDING","enabled":false},
    {"id":"lbapi9","status":"PENDING","enabled":false},
    {"id":"slapibf","status":"PENDING","enabled":false},

Không có API proxy tùy ý, tải xuống hoặc relay stream. Quyền ở cấp provider không thay thế quyền của từng video.

4. Catalog API (legacy alias)

GET/health

Kiểm tra trạng thái dịch vụ và cấu hình. Health response không phải bằng chứng rằng upstream provider hoặc video playback đang hoạt động.

GET/api/providers

Liệt kê provider đã cấu hình và trạng thái cấu hình công khai. Không trả API key hoặc secret.

GET/api/catalog/categories?sourceId={sourceId}

Lấy danh mục từ provider. Route cũ chỉ giữ tương thích và đang trả trạng thái chờ quyền. Ứng dụng frontend đã chuyển sang /api/videos.

GET/api/catalog/videos?page=1

Truy vấn catalog có phân trang và bộ lọc tùy chọn. Tham số page bắt đầu từ 1.

{
  "provider": { "id": "souavzy", "name": "Souavzy · Main" },
  "items": [],
  "page": 1,
  "pageCount": 0,
  "total": 0,
  "limit": 20
}

4. Provider API

GET/api/providers/{sourceId}/categories

Lấy danh mục của một provider cụ thể.

GET/api/providers/{sourceId}/videos?page=1&keyword={keyword}&categoryId={categoryId}

Lấy danh sách video của provider, hỗ trợ phân trang và lọc.

GET/api/providers/{sourceId}/videos/{videoId}

Lấy metadata chi tiết video từ provider đã cấu hình. Không đảm bảo mọi video đều có URL phát hợp lệ.

5. Xác thực & quản trị

Provider Registry Preview cung cấp luồng đăng nhập quản trị bằng session cookie HttpOnly. Không gửi token bootstrap hoặc mật khẩu qua query string, URL, log frontend hay kho mã nguồn.

Quan trọng: Auth là same-origin, không phải CORS API

Toàn bộ luồng đăng nhập và quản trị phải được gọi trên chính origin của Provider Registry Worker. Mở trang đăng nhập trực tiếp tại https://clipviet-provider-registry-preview.huynhthuongg2505-f9b.workers.dev/login; sau khi đăng nhập, tiếp tục dùng cùng hostname tại /admin. Không gọi các route Auth từ origin Cloudflare Pages hoặc một domain frontend khác.

Trong mã nguồn Worker, handleAuth() từ chối request có header Origin khác origin của Worker đối với các thao tác POST, trả 403 Origin mismatch. Các route Auth được dispatch trước middleware CORS của Provider Registry; do đó CORS allowlist của API registry không cấp quyền cross-origin cho Auth.

Cookie phiên cv_session là cookie host-only với thuộc tính HttpOnly, Secure, SameSite=Strict. Trình duyệt gửi cookie tự động khi điều hướng và gửi request same-origin; không đọc hoặc sao chép cookie từ JavaScript.

MethodPathMô tả
GET/auth/statusCho biết có cần khởi tạo Admin ban đầu hay không.
POST/auth/bootstrapKhởi tạo Admin đầu tiên; yêu cầu bootstrap token, Gmail và mật khẩu riêng.
POST/auth/loginĐăng nhập và tạo session cookie.
GET/auth/meKiểm tra session hiện tại.
POST/auth/logoutHủy session hiện tại.

API quản trị yêu cầu role phù hợp. Các thao tác duyệt connector/quyền nội dung cần vai trò và bằng chứng tương ứng; không sử dụng endpoint quản trị như API catalog công khai.

6. CORS, HTTP và lỗi

  • Chỉ dùng HTTPS.
  • Browser cross-origin request cần Origin khớp allowlist; preflight sử dụng OPTIONS.
  • Không thêm path, query hoặc fragment vào CORS origin.
  • Không đưa Authorization token hoặc bootstrap secret vào URL.
  • Client cần xử lý tối thiểu các mã 400, 401, 403, 404, 409, 429 và 5xx.
StatusÝ nghĩa
400Tham số hoặc request không hợp lệ.
401Chưa xác thực hoặc session không hợp lệ.
403Origin, role hoặc policy không cho phép.
404Không tìm thấy tài nguyên/route.
409Xung đột trạng thái hoặc điều kiện nghiệp vụ chưa đạt.
429Vượt giới hạn thử đăng nhập.
5xxLỗi dịch vụ hoặc upstream.

7. Playback & quyền phân phối

Catalog API chỉ cung cấp metadata/đường dẫn do upstream trả về. Trình phát phải kiểm tra HTTPS, MIME, HLS/MP4 và khả năng tương thích thiết bị. Không proxy hoặc relay media nếu chưa có thiết kế và quyền phù hợp.

Rights gate

Provider hoặc nội dung ở trạng thái PENDING không được coi là đã được cấp quyền. Chỉ phát nội dung có bằng chứng sở hữu/cấp phép, phạm vi sử dụng, khu vực và thời hạn còn hiệu lực được xác minh.

Safari trên iPhone có thể phát HLS native khi media server hỗ trợ. Cần kiểm thử thiết bị thực tế; tài liệu này không tuyên bố playback đã được nghiệm thu.

8. Ví dụ tích hợp

Fetch danh sách video

const API = "https://clipviet-catalog-api-preview.huynhthuongg2505-f9b.workers.dev";

const url = new URL("/api/catalog/videos", API);
url.searchParams.set("page", "1");
url.searchParams.set("sourceId", "souavzy");

const response = await fetch(url, {
  method: "GET",
  headers: { "Accept": "application/json" }
});

if (!response.ok) {
  throw new Error(`Catalog API error: ${response.status}`);
}

const catalog = await response.json();
console.log(catalog.items);

Kiểm tra API health

curl -i \
  -H "Accept: application/json" \
  "https://clipviet-catalog-api-preview.huynhthuongg2505-f9b.workers.dev/health"

9. Giới hạn và trạng thái phát hành

  • Tài liệu này mô tả API Preview, không phải cam kết SLA hoặc API Production.
  • Không có Production API base URL được xác nhận trong bản phát hành này.
  • Provider status và rights status phải được kiểm tra trực tiếp; không suy luận từ việc provider xuất hiện trong danh sách.
  • Không công bố API key, Telegram token, bootstrap token hoặc thông tin đăng nhập.
  • Đường dẫn API có thể thay đổi khi Worker contract được cập nhật; hãy đối chiếu với bản triển khai thực tế trước khi tích hợp Production.
